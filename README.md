# وب‌سایت خدمات آلفا — shirazpcrepair.ir

این مخزن فایل‌های وب‌سایت عمومی خدمات آلفا را نگه می‌دارد و برای انتشار ایستا از GitHub Pages استفاده می‌کند.

## ساختار فعلی

- `index.html`: صفحه اصلی
- `style.css`: استایل مشترک صفحات اصلی
- `laptop-repair-*.html` و `computer-repair-*.html`: صفحات تعمیر لپ‌تاپ و کامپیوتر
- `modem-repair-shiraz.html`، `industrial-board-repair-shiraz.html`، `medical-board-repair-shiraz.html` و `data-recovery-shiraz.html`: خدمات تخصصی
- `shop.html`: معرفی محصولات و استعلام از طریق واتساپ؛ در حال حاضر فروشگاه تراکنشی یا ثبت سفارش در پایگاه داده نیست
- `corporate.html`: فرم درخواست سازمانی که پیام را برای ارسال در واتساپ آماده می‌کند
- `estimate.html`: تخمین قیمت در مرورگر
- `software.html`: صفحه اولیه معرفی نرم‌افزارها؛ کارت‌ها جایگاه خالی هستند و نباید به‌عنوان برنامه آماده دانلود تلقی شوند
- `blog.html` و `blog-*.html`: وبلاگ
- `sitemap.xml` و `robots.txt`: فایل‌های راهنمای خزنده‌های موتورهای جست‌وجو
- `404.html`: صفحه خطای آدرس ناموجود

## روش انتشار

سایت بر اساس فایل‌های موجود در شاخه `main` و تنظیمات GitHub Pages منتشر می‌شود. ویرایش فایل‌های HTML و CSS در این مخزن باعث انتشار نسخه جدید پس از تکمیل build/deployment گیت‌هاب می‌شود. پیش از تغییرات وسیع، تغییرات را در یک شاخه جداگانه یا با یک commit قابل بازگشت نگه دارید.

## محدودیت مهم میزبانی

GitHub Pages سرویس میزبانی **ایستا** است: فایل‌های HTML، CSS و JavaScript را ارائه می‌کند، اما برنامه سمت سرور مانند PHP/Python و پایگاه داده دائمی برای ثبت سفارش ندارد. مستندات رسمی GitHub همچنین Pages را برای وب‌سایت‌هایی که هدف اصلی آن‌ها تجارت الکترونیک است یا برای تراکنش‌های حساس (مانند ارسال رمز عبور و شماره کارت) در نظر نگرفته است.

بنابراین با میزبانی فعلی:
- معرفی خدمات، محتوا، نمونه‌کار، لینک تماس و صفحه معرفی نرم‌افزار امکان‌پذیر است.
- فرم جاوااسکریپتی به‌تنهایی سفارش خصوصی و ماندگار ذخیره نمی‌کند.
- هرگز رمز عبور مدیر، توکن API یا کلید محرمانه را در HTML/JavaScript عمومی قرار ندهید.
- برای پنل مدیریت واقعی و ذخیره امن سفارش‌ها، یک سرویس سمت سرور یا بک‌اند مدیریت‌شده لازم است. تا زمانی که میزبانی فقط GitHub Pages است، سفارش‌گیری فعلی باید به مسیر تماس/واتساپ محدود بماند و ادعای «پنل سفارش واقعی» نشود.

## نکات نگهداری

1. پس از تغییر لینک منو، بررسی کنید همان لینک‌ها در فوتر و صفحات سفارشی نیز وجود داشته باشند.
2. صفحه `software.html` فعلاً دارای `noindex` است و عمداً در نقشه سایت وارد نشده؛ پس از افزودن اطلاعات واقعی و آماده انتشار باید این وضعیت بازبینی شود.
3. اطلاعات حساس مشتریان را در فایل‌های عمومی مخزن، URLها، فرم‌های بدون بک‌اند یا Issues عمومی GitHub ثبت نکنید.
4. قبل از هر تغییر SEO، وضعیت فعلی صفحات و نشانی canonical را حفظ و اعتبارسنجی کنید.
